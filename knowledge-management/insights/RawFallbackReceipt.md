# RawFallbackReceipt

**Type:** Detail

## What It Is

RawFallbackReceipt is implemented in `src/live-logging/raw-fallback.js`, a two-export, zero-import leaf module consisting of the `RAW_FALLBACK_PREFIX = '[Raw]'` constant and the `isRawFallbackSummary()` predicate. Despite its small footprint, the module's own docstring frames it not as a formatting utility but as the fix for a specific class of bug: the `[Raw]` prefix used to be duplicated verbatim across `ObservationWriter._fallbackSummary`, `ObservationWriter._classifyQuality`, and `scripts/backfill-raw-observations.mjs`, and one copy silently drifted from the others, causing `ObservationExporter.keepInExport` to misclassify legitimate placeholder rows. The component's semantic purpose is captured in its name: a `[Raw]` row is a "receipt" — proof that a turn was captured even though the LLM summarization pipeline (the proxy) was unreachable at write time — not a failure to be discarded.

## Architecture and Design

The core architectural pattern here is single-source-of-truth extraction to eliminate string-literal drift: rather than each of four sites (writer, classifier, backfill script, exporter) independently re-implementing the `[Raw]` check, they all now import from this one leaf module. Equally significant is the deliberate dependency-boundary cut: `raw-fallback.js` has no imports specifically so `ObservationExporter.js` — a lightweight read/export-path module — never has to pull in `ioredis` and `@fwornle/km-core` transitively through `ObservationWriter.js`, a heavyweight producer module. This lets producer and consumer share exact matching logic without depending on each other, both instead depending on this shared leaf.

The component also embodies a "receipt pattern": a placeholder record whose presence itself proves successful capture despite a pipeline failure, with the full payload preserved (`metadata.messages`) for deferred reprocessing. This is a two-sided contract — the write side stamps the prefix as a promise of recoverability, and consumers (the backfill script, the exporter) must honor that promise by treating the row as pending rather than empty, rather than as noise.

## Implementation Details

The matcher, `summary.trimStart().toLowerCase().startsWith(RAW_FALLBACK_PREFIX.toLowerCase())` (raw-fallback.js:32-35), is deliberately case-insensitive and whitespace-tolerant. This isn't defensive boilerplate; the docstring ties it to an observed historical data shape — rows dated 2026-05-28 that read `"[Raw] needs backfill"` in lowercase — so the normalization exists to handle real drift already present in stored data, not hypothetical future drift.

The consumer side is concretely realized in `ObservationExporter.keepInExport(row)` (`src/live-logging/ObservationExporter.js`), whose inline comment documents the exact incident this guards against: conflating a `[Raw]` receipt with a genuine content-free "low quality" observation once caused 26 turns' worth of rows to vanish from every downstream consumer, since the dashboard endpoint `/api/coding/observations` reads exclusively from this exporter's JSON output via `ColdStoreReader`. Notably, the fix is scoped narrowly: the exception is keyed on the summary text via `isRawFallbackSummary`, and `quality` deliberately stays `'low'` so `ObservationConsolidator` (ObservationConsolidator.js:1392,1687) continues excluding contentless rows from digest synthesis. Quality tagging and export-inclusion are thus intentionally decoupled — two different predicates over the same row, letting the dashboard render the receipt faintly while consolidation logic still ignores it.

## Usage Guidelines

Any new site that needs to recognize a fallback/raw row must import `isRawFallbackSummary` from `raw-fallback.js` rather than re-implementing a prefix check — this is precisely the drift this module was created to prevent. Developers should not "fix" the exporter's exception by promoting `[Raw]` rows to a distinct quality tier; the decoupling of quality (`'low'`) from export inclusion is intentional and preserves consolidator behavior. Because the matcher's case-insensitivity and whitespace tolerance are grounded in an actual historical data shape, they should not be simplified to a strict-equality check without checking for similarly malformed legacy rows. Finally, this module should remain dependency-free — adding imports here would reintroduce the exact coupling (`ObservationExporter` forced to pull in `ioredis`/`km-core`) that its extraction was designed to avoid.
