# LearningSourceClassifier — Technical Insight Document

## What It Is

`LearningSourceClassifier` is not a single class or file but a distributed convention centered on `isOnlineLearned()`, canonically defined in `integrations/unified-viewer/src/graph/learning-source.ts` and consumed by `integrations/unified-viewer/src/graph/color-fallback.ts` and `integrations/unified-viewer/src/graph/D3GraphCanvas.tsx`. Its job is simple in interface — reduce a node's provenance metadata to a single boolean, "was this learned online?" — but it functions as the sole arbiter of that fact across the graph viewer. As a child concept under both `OnlineLearning` and `GraphViewerHierarchy`, it exists specifically to answer one narrow question consistently everywhere it's asked, rather than being derived ad hoc from `metadata.source` at each call site.

The classifier's predecessor was a naive `source === 'auto'` string check; `color-fallback.ts` explicitly documents that this was replaced because "the data stamps ETM/consolidator output as online far more often than auto." This is a case where the classification logic itself had to absorb real-world data drift, rather than being something fixed once at design time.

## Architecture and Design

The dominant pattern here is **single-source-of-truth classification with channel separation**. `isOnlineLearned()` is consumed identically by multiple surfaces, but its boolean output is projected onto different, non-conflicting visual channels depending on context: `nodeFillColor()` in `color-fallback.ts` ignores learning-source entirely (fill is class-hierarchy-only), while `ONLINE_RING_COLOR` is applied as an independent ring overlay keyed on the same predicate. This separation is explicitly justified by a retconned bug — "Insights are not purple" — caused by an earlier single-channel design that conflated fill and provenance into one visual signal.

D3GraphCanvas.tsx states plainly that "the canvas, Legend, filter and History sidebar all share" this one predicate, marking `isOnlineLearned()` as a convergence point after a prior state where multiple UI surfaces independently guessed at learning provenance from raw entity metadata. This mirrors the consolidation pattern already documented for `nodeFillColor()` elsewhere in the codebase — disagreeing implementations unified behind one function.

A second pattern, the **Strangler Fig / compatibility shim**, governs migration: the deprecated `isOnlineSource(source?: string | null)` in `color-fallback.ts` is kept alive as a thin wrapper delegating to `isOnlineLearned(node)`, rather than being deleted with call sites updated. This mirrors `calculateStepAwareEta` delegating to `calculateDynamicEta` in `ukb-workflow-modal.tsx` — a house style of preserving old signatures over aggressive cleanup.

## Implementation Details

Although the classifier's public interface is a single boolean, its `~138 entities carrying no source at all` comment in `color-fallback.ts` reveals that the real implementation handles missing/undefined source data via additional heuristics — a "digest-shape fallback" beyond simple string comparison. This means the innocuous boolean predicate masks non-trivial classification logic accumulated from real dataset edge cases, not unlike how `nodeFillColor()` and `nodeShapeFor()` hide ancestor-chain walking behind a simple lookup call.

Consumers key off this boolean in structurally different ways: `nodeFillColor()` never touches it (fill remains purely a function of class hierarchy, per the `HierarchyCycleBreaking` and `DeriveParentsHierarchyReduction` sibling components' `while (cur && !seen.has(cur))` ancestor walks), while ring rendering logic branches directly on `isOnlineLearned(node)` to select `ONLINE_RING_COLOR`. This is deliberately low-dimensional output — a single boolean, not an enum or object — kept that way even though the team, per the observations, "learned from a prior incident that even simple boolean derivations drift when duplicated across files."

## Integration Points

The classifier's primary integration point is `D3GraphCanvas.tsx`, which imports `isOnlineLearned` directly from `./learning-source` and threads it through canvas rendering, Legend, filter, and History sidebar logic — all reportedly sharing this one import rather than re-deriving provenance locally. `color-fallback.ts` integrates it both directly (via the canonical function) and indirectly (via the deprecated `isOnlineSource` wrapper), keeping older call sites functional during migration.

Structurally, `D3GraphCanvas.tsx` sits under `GraphViewerHierarchy` alongside siblings like `DeriveAncestryFromStorePath` and `ComputeAncestryPathExtraction`, which reconcile store-derived (`pathToSelected`) versus locally computed (`computeAncestryPath()`) ancestry sets using a "writer's intent wins, but degrade gracefully" policy. `LearningSourceClassifier` doesn't participate in that reconciliation directly, but it lives in the same file and rendering path, reflecting the broader architectural tension of this component: D3GraphCanvas.tsx is an explicit port from a Redux-based `GraphVisualization.tsx` to Zustand, maintained in parallel with a separate Sigma/WebGL canvas (`graph-builder.ts`), meaning shared predicates like `isOnlineLearned()` help keep visual semantics consistent across otherwise divergent rendering engines.

## Usage Guidelines

Developers should always call `isOnlineLearned()` (or its module `learning-source.ts`) rather than reintroducing inline `metadata.source === 'auto'`-style checks — the codebase's own history shows this drifts as underlying data conventions change. When encountering `isOnlineSource()` in `color-fallback.ts`, treat it as a deprecated compatibility wrapper only; new code should call the canonical function directly, but existing call sites need not be migrated immediately, consistent with the project's Strangler Fig convention.

Because fill color and ring color are intentionally orthogonal channels, do not conflate them: fill communicates ontology/class hierarchy (see `nodeFillColor()`'s ancestor walk, echoed in `nodeShapeFor()` and guarded against cycles via the `seen` set pattern), while the ring communicates online-learning provenance. Reintroducing a single-channel encoding risks recreating the "Insights are not purple" bug. Finally, be aware that the classifier's real complexity — handling ~138 sourceless entities and other edge cases — is nontrivial even though the interface is a boolean; treat changes to `learning-source.ts` as touching shared, load-bearing logic across canvas, Legend, filter, and History surfaces simultaneously.

Both functions walk a registry parent chain (`cur = reg?.parent`) with an identical guard: `const seen = new Set<string>(); while (cur && !seen.has(cur)) { seen.add(cur); ... }`. Without this guard, a malformed ontology registry entry (e.g. class A declaring parent B, B declaring parent A) would infinite-loop the walk on every single node render using that class — since these are called per-node inside D3GraphCanvas's render path, a cyclic registry would hang the whole canvas, not just misrender one node.
