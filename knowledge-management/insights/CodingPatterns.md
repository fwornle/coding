## Implementation Details

Since there is no source directory, "implementation" manifests as concrete rules embedded in specific tooling and scripts referenced by the child observations. DocumentationStyleGuide mandates that `.puml` diagram sources live under `docs/puml/`, distinguishing version-controlled authoring artifacts from generated build outputs. TestingPractices is grounded in a real defect: test-inventory tooling built around older heuristics (matching `mocha`/`jest`-style imports) silently skipped files importing from `node:test`, undercounting coverage without raising errors — the fix requires explicit recognition of the `node:test` specifier. Closely related is the `suiteOwnership()` guard pattern, which forbids silently dropping test files from the active suite; any exclusion must carry an explicit, verified declaration, guarding against a shrinking test count being mistaken for a healthier codebase.

DataIntegrityPatterns documents the "Metadata Merge Bug — Destructive Overwrite Pattern," where manifest-level and graph-level entity descriptions drifted out of sync during merges, and captured-by edge counts proved unstable across multi-stage fixes. The established discipline is to close tracking only once verified with freshly measured figures, never carrying forward stale assumed numbers. PatternVerificationTooling encodes the "Post-Rewrite Render Error Triage" discipline: after a large rewrite, every observed render error must be classified as pre-existing or a genuine regression before being prioritized or attributed — implying baseline error states should be captured before large refactors to make this classification possible.

## Integration Points

CodingPatterns' children integrate directly with CI and build infrastructure rather than with each other's runtime code. The Unified Viewer's CI Build/Test Gate Wiring anti-pattern — a build script chaining commands with `;` instead of `&&` and discarding `tsc` output — meant TypeScript compilation errors never failed the build; the generalized convention is that command chaining must use `&&` so failures short-circuit the pipeline and tool output (especially type-checker output) must never be redirected away from CI logs. Separately, the CI Test Flakiness observation on tmux mouse selection and `npm ci` shows how overly broad `.gitignore` rules can accidentally exclude required lockfiles like `package-lock.json`, producing CI-only failures unreproducible locally — establishing a debugging heuristic to check `.gitignore` scope and lockfile presence before assuming flakiness. These patterns tie CodingPatterns' conventions into DockerizedServices' build pipelines and into the broader Coding root's CI gates, even though CodingPatterns itself owns no executable infrastructure.

## Usage Guidelines

Developers should treat CodingPatterns as a reference manual rather than a code dependency: consult its children — DocumentationStyleGuide, TestingPractices, DataIntegrityPatterns, PatternVerificationTooling, ArchitectureGuidelines — when authoring diagrams, tests, merge logic, or post-rewrite verification, rather than expecting an importable module. Concretely: keep `.puml` sources in `docs/puml/`; never let test files vanish from the suite without an explicit `suiteOwnership()`-style declaration; ensure test-inventory tooling recognizes `node:test` imports; always re-measure (never assume) metrics like captured-by edge counts before closing a data-integrity fix; classify render errors as pre-existing versus regression before assigning blame after rewrites; and enforce `&&`-chained, output-preserving CI scripts so type errors and lockfile mismatches surface immediately rather than silently passing.
