# TokenUsageAdapters — Technical Insight Document

## What It Is

TokenUsageAdapters is a SubComponent of LiveLoggingSystem implemented across three files: `lib/lsl/token/copilot-events-tail.mjs`, `lib/lsl/token/opencode-token-rows.mjs`, and `lib/lsl/token/token-db.mjs`. It exists to close a structural gap in the Coding project's LLM accounting model: the rapid-llm-proxy running at `:12435` is the authoritative writer of `token_usage.db`, but three foreground agents — Claude Code, Copilot CLI, and OpenCode — each have execution paths that bypass the proxy entirely. Rather than intercepting network calls, this subsystem reconstructs missing token rows *after the fact* from each agent's own persistence layer: Copilot's `events.jsonl`, and OpenCode's SQLite `opencode.db`. It is explicitly a "second writer" — a best-effort compensation layer, not a clean instrumentation point.

## Architecture and Design

The dominant pattern is **second-writer/compensating-write**: adapters write into a database (`token_usage.db`) owned and schema-controlled by an external process, rather than instrumenting the call site. This forces two defensive architectural responses. First, **id-space partitioning** (decision D-06): `token-db.mjs` defines `ADAPTER_USER_HASH_CLAUDE` ('cladpt'), `ADAPTER_USER_HASH_COPILOT` ('copadt'), and `ADAPTER_USER_HASH_OPENCODE` ('opnadt') as synthetic `user_hash` values conforming to the proxy's own `/^[a-z][a-z0-9]{5}$/` validation (`token-usage.ts:46-47`), letting multiple writers share one SQLite table without colliding — a lightweight substitute for real multi-writer coordination. Second, **defensive schema introspection**: `insertShapeFor()` in `token-db.mjs` probes `PRAGMA table_info(token_usage)` at runtime (WeakMap-memoized) to detect proxy-driven migrations (e.g., ROUTING_COLUMNS), meaning INSERT shape is discovered per-connection rather than fixed at authorship time.

A second cross-cutting pattern is **best-effort, non-throwing error isolation** (D-08): failures in `insertTokenRow` or the `onTokenRow` callback are deliberately routed to isolated stderr channels rather than propagating, so token-accounting bugs can never corrupt the primary LSL observation pipeline. This reflects TokenUsageAdapters' subordinate role beneath its parent, LiveLoggingSystem — it runs parallel to session-windowing and file-routing but must never threaten transcript-capture integrity.

## Implementation Details

`TokenDbWriter` (in `token-db.mjs`) implements `insertTokenRow()` as a non-atomic "read MAX(id), then INSERT" sequence, retried up to `INSERT_ID_RETRY_ATTEMPTS` (3) times. Its own docstring (WR-05 re-review) acknowledges the race: a concurrent writer into the same adapter's `user_hash` space between SELECT and INSERT throws `SQLITE_CONSTRAINT` on the composite `(user_hash, id)` primary key. The catch block disambiguates via a secondary query on `(user_hash, tool_call_id)` — if that pair already exists, it's a legitimate dedup and the row is dropped (`return false`); otherwise it retries. This conflates two distinct failure semantics (id-race vs. duplicate) into one exception branch, a noted maintenance risk.

`OpencodeTokenRows` (`buildOpencodeTokenRows` in `opencode-token-rows.mjs`) enforces a no-double-count invariant (D-04) via `BYPASS_PROVIDERS`, a hardcoded `Set(['github-copilot'])`. OpenCode sessions on the 'anthropic' provider are assumed proxy-routed and skipped; the comment explicitly flags this as manual, "extend deliberately" territory.

`CopilotEventsTailWatcher` (`copilot-events-tail.mjs`) polls `events.jsonl` and confronts a hard data-loss constraint: Copilot CLI only emits subagent lifecycle bookends, never message content. `buildStubObservation()` fabricates a synthetic two-message exchange, stamping every such row `lsl_incomplete: true` with the locked, test-asserted `COPILOT_LSL_INCOMPLETE_NOTE`. Separately, `tailEventsFile()` was extended (Phase 69 Plan 69-06) with an `onTokenRow` callback fired on `session.shutdown` lines, whose failures are isolated to a dedicated stderr message rather than the shared `onError` path.

## Integration Points

TokenUsageAdapters sits beneath LiveLoggingSystem, alongside siblings LSLConfigValidator, RedactionConfigManager, LiveTranscriptWatchers, and ObservationWriter — parallel to but architecturally subordinate to session-transcript capture. It shares its id-partitioning scheme directly with **MultiUserHashManager**, which documents the same `ADAPTER_USER_HASH_*` constants as decision D-06. It overlaps structurally with **LiveTranscriptWatchers**, which notes that Copilot's polled tail (`TAIL_POLL_INTERVAL_MS=200ms`) and OpenCode's pull-based SQLite read at measurement-stop are fundamentally different consistency models rather than one reusable watcher abstraction — a distinction TokenUsageAdapters inherits directly in its own two adapter implementations.

Internally, its children are `OpencodeTokenRows`, `TokenDbWriter`, and `CopilotEventsTailWatcher`, corresponding directly to the three source files. Both `TokenDbWriter` and `OpencodeTokenRows` depend on external, non-owned schemas (`token_usage.db`, `opencode.db`) requiring runtime introspection rather than compile-time contracts. Notably, database access itself is inconsistent: `token-db.mjs` loads `better-sqlite3` via `createRequire(import.<COMPANY_NAME_REDACTED>.url)` (a CJS-in-ESM native-binding workaround), while `opencode-token-rows.mjs` uses a standard ESM `import Database from 'better-sqlite3'`.

## Usage Guidelines

Developers extending or modifying these adapters must treat failures as non-fatal by design — any new write path should follow D-08 and route errors to isolated stderr channels, never propagate. When adding a new bypass provider to OpenCode, `BYPASS_PROVIDERS` in `opencode-token-rows.mjs` must be updated manually and deliberately; there is no runtime verification of this invariant. Any schema assumption against `token_usage.db` should go through `insertShapeFor()`'s introspection pattern rather than hardcoding column lists, since the proxy owns and can migrate that schema independently.

The uid-ownership check (`isOwnedByMe()` in `copilot-events-tail.mjs`, `ownedDbPath()` in `opencode-token-rows.mjs`) is duplicated rather than shared — a consolidation candidate, but until refactored, changes to one must be mirrored in the other. The `lsl_incomplete` flag and `COPILOT_LSL_INCOMPLETE_NOTE` string are test-asserted and locked; they should be treated as a permanent data-contract element, not a placeholder to remove. Finally, the `findLiveLockFile()` heuristic (`LOCK_STALE_GRACE_MS` = 10 minutes) is a known-soft liveness check ("landmine #5") — anyone relying on Copilot session liveness detection should be aware of its false-positive/false-negative window rather than assuming precise process-alive semantics.
